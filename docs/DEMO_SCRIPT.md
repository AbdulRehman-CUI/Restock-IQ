# RestockIQ — approximately three minutes

Preparation: install dependencies, run `python -m app.cli prepare-demo` once, then start the API and UI in separate terminals using README. The IDs below identify the preserved Phase 3 evidence; choose the matching short IDs in the sidebar’s Advanced analysis selection. More recent runs may also exist. Select synthetic dataset **229e8694**, model **48f53d36**, forecast **9535e13b**, and base **edd2f0b6**. Analysis origin: 15 October 2026; expected demand: 16 October–14 November 2026, 600 rows / 20 products. Values were re-read from the API for this handoff.

**0:00–0:25 — the problem.** A retailer can appear profitable against an old purchase cost while the next shipment costs more. Historical gross difference does not establish replacement funding or net profit. RestockIQ connects expected unit demand, recorded stock and receipts, replacement cost, and explicit purchasing decisions.

**0:25–0:55 — Overview.** Confirm the synthetic provenance and historical origin. Base order-now count: 7; expedite: 5; no-additional-action shortage count: 19. Explain that the cash card only includes order-now candidates. It is estimated landed replenishment cost, not revenue or an invoice. Read its value and inclusion counts on screen. Existing eligible receipts are included, but newly recommended orders are not inserted into stock projections.

**0:55–1:30 — Products.** In Overview, open Additional filters & columns, filter Supplier currency to USD, and inspect one imported-currency product (these records remain synthetic). Compare observed sales with expected demand, pointing out the forecast divider and censored/closed-day markers. Inspect historical purchase cost, replacement cost, quote/FX components, suggested price, target margin, and backend reasons. Show reliable receipts and uncertain overdue POs. Mark reviewed with the note “Demo review”; explain that this is a local audit action only.

**1:30–2:10 — Scenarios.** Select the preserved base. Choose **Phase 3 demonstration**, review FX +10%, supplier change 0%, freight PKR 0, lead +7 days, margin override 20%, then explicitly press **Run scenario**. Alternatively select saved scenario **c03f48fb** and its saved recommendation **68bd9829** to avoid creating another run. The preserved scenario has 19 order-now and 18 expedite products. Explain that the 20% margin override can independently change prices. Demand stays unchanged; no customer price response is estimated. Inspect one product’s cost, shortage date, quantity and cash changes. Coverage cash compares all common calculable coverage candidates; the Base & scenario table separately shows order-now cash and its inclusion counts.

**2:10–2:40 — Model Performance.** Choose 7 days. Validation MAE is baseline 3.9645 versus Random Forest 3.7846 units/product-day (838 paired targets). Test MAE is 4.1963 versus 3.9139 (860 targets); test WAPE is 39.18% versus 36.55%. WAPE is error, not accuracy. Use the baseline-better filter in the per-product table to inspect cases where baseline wins. Switch Evaluation context between held-out test and validation. Select 30 days and show insufficient cumulative coverage.

**2:40–3:00 — handoff.** Download the visible forecast, recommendations and metadata. These synthetic results establish functionality, not measured savings. The next step is a retailer pilot with observed availability, demand, receipts and landed costs, followed by prospective evaluation before any operational adoption.
